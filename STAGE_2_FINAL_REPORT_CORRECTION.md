## 2. Investigation of the Scenario Discrepancy

### Root Cause Analysis
In `SimPySimulationEngine.__init__` (`backend/app/simulation/engine.py`), the constructor defines:
```python
def __init__(
    self,
    num_students: int = 10,
    protocol: str = "TCP",
    bandwidth: Any = "1 Mbps",
    delay: Any = "20ms",
    queue_capacity: int = 50,
    simulation_duration: float = 10.0,
    scenario_name: str = "Normal Traffic",  # Default parameter fallback
    traffic_intensity: str = "Medium",
    ...
):
```
- In `traffic.py`:
  - `"Normal Traffic"` specifies: `avg_packet_size = 1024 bytes`, `base_arrival_interval = 0.050 s`.
  - `"Online Classroom"` specifies: `avg_packet_size = 512 bytes`, `base_arrival_interval = 0.035 s` (modeling e-learning audio frames + slide bursts).
- In the original Stage 2 implementation report (`stage2_simpy_engine_report.md`), the sample experiment passed `scenario_name="Online Classroom"`, which produced **11,994 packets** (pre-fix, before window clamping).
- During the subsequent bug-fix turn, the script `scratch/run_sample_experiment.py` omitted the `scenario_name` parameter:
  ```python
  engine = SimPySimulationEngine(
      num_students=10, protocol="TCP", bandwidth="10 Mbps", delay="20ms", simulation_duration=5.0, seed=42
  )
  ```
  Because `scenario_name` was omitted, the engine defaulted to `"Normal Traffic"`. At $1024\text{ B}$ per packet, it generated **6,034 unique packets**.
- The Bug Fix report mistakenly labeled this 6,034-packet output as `"Online Classroom"` without realizing that the constructor had defaulted to `"Normal Traffic"`.

### Data Volume Equivalence Proof
Both runs transferred virtually identical payload volumes over the 10 Mbps bottleneck link:
- **Normal Traffic (1024-byte packets):**
  $$6,034\text{ unique packets} \times 1024\text{ bytes} = 6,178,816\text{ bytes} \quad (\approx 6.18\text{ MB})$$
  $$\text{Goodput} = \frac{6,178,816\text{ bytes} \times 8}{5.071994\text{ s} \times 1000} = 9,745.78\text{ Kbps} \quad (97.46\% \text{ link utilization})$$
- **Online Classroom (512-byte packets):**
  $$11,998\text{ unique packets} \times 512\text{ bytes} = 6,142,976\text{ bytes} \quad (\approx 6.14\text{ MB})$$
  $$\text{Goodput} = \frac{6,142,976\text{ bytes} \times 8}{5.049\text{ s} \times 1000} = 9,733.29\text{ Kbps} \quad (97.33\% \text{ link utilization})$$

### Official Scenario Designation
The previous report's label of `"Online Classroom"` for the 6,034-packet run was an unintentional parameter omission. The official, intended university e-learning reproducibility benchmark is **Online Classroom** (`scenario_name="Online Classroom"`, 512-byte packets, 11,998 unique packets).

## 3. Unique Packets vs. Transmission Attempts

### Counter Definitions in `backend/app/simulation/event_recorder.py`

| Internal Counter | Metric Key | Definition | Value (Online Classroom) |
| :--- | :--- | :--- | :--- |
| `len(self.unique_generated)` | `packets_sent` | Cardinality of unique keys `(src_node, seq_num)`. Incremented **only** on initial datagram creation (`is_retransmit=False`). | **11,998 unique packets** |
| `self.total_transmissions` | `total_transmissions` | Total number of packet dispatch processes initiated (initial generation $+$ retransmission attempts). | **12,091 total attempts** |
| `self.retransmissions_count` | `retransmissions` | Total number of retransmission attempts dispatched for dropped frames (`is_retransmit=True`). | **93 retransmissions** |
| `len(self.dropped_packets)` | `packets_dropped` | Total number of failed physical transmission attempts (DropTail buffer overflows). | **93 attempt drops** |
| `len(self.unique_dropped)` | `unique_dropped_packets` / `lost_packets` | Number of unique packets in terminal `STATE_DROPPED` at simulation completion. | **0 terminal drops** |
| `len(self.unique_delivered)` | `packets_received` | Number of unique packets accepted by destination LMS application (`STATE_DELIVERED`). | **11,998 unique packets** |
| `self.total_offered_bytes` | `total_offered_bytes` | Total payload bytes emitted across all transmission attempts ($12,091 \times 512\text{ B}$). | **6,190,592 bytes** |
| `self.total_link_transmitted_bytes` | `total_link_transmitted_bytes` | Payload bytes of packets that successfully dequeued and completed physical serialization onto the channel wire ($11,998 \times 512\text{ B}$). | **6,142,976 bytes** |
| `self.total_delivered_bytes` | `total_delivered_bytes` | Payload bytes delivered to destination application layer ($11,998 \times 512\text{ B}$). | **6,142,976 bytes** |

### Mathematical Accounting Invariants
1. **Packet Conservation:**
   $$\text{Unique Generated} = \text{Unique Delivered} + \text{Unique Dropped} + \text{In-Transit}$$
   $$11,998 = 11,998 + 0 + 0 \quad (\text{Passed})$$
2. **Attempt Conservation:**
   $$\text{Total Transmissions} = \text{Unique Generated} + \text{Retransmission Attempts}$$
   $$12,091 = 11,998 + 93 \quad (\text{Passed})$$
3. **Byte Conservation:**
   $$\text{Total Offered Bytes} = \text{Physical Serialized Bytes} + \text{Dropped Attempt Bytes}$$
   $$6,190,592 = 6,142,976 + (93 \times 512) = 6,142,976 + 47,616 \quad (\text{Passed})$$

The 93 failed transmission attempts are **attempt drops** logged in `dropped_packets`. They are **never** added to `unique_generated` and do **not** inflate the unique packet count.
